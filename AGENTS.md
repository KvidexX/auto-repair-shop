# Архитектура и границы изменений

- `main.py` — CLI (`--demo`, `--screenshot`, `--screen`, `--dialog`, `--order-card`), QApplication, тема и жизненный цикл Database.
- `autoservice/app.py` — MainWindow, навигация и справочники клиентов/автомобилей; `dialogs.py` — их формы.
- `styles.py` — общий QSS; `ui.py` — Fusion/палитра, выпадающие списки, календарь, иконки и делегаты.
- `data.py` — чистые бизнес-правила, время и нормализация; `demo_data.py` — вымышленные наборы, генераторы и явная загрузка тестовых данных.
- `database.py` — SQLite API, схема v2 и миграция 1 → 2; `persistence.py` — публикация снимков UI после COMMIT.
- `orders.py`, `appointments.py`, `services.py`, `history.py` — соответствующие страницы и формы. История использует общую коллекцию заказов.
- Внутри autoservice используйте относительные импорты; из main.py и тестов — `autoservice.*`. Тестовые помощники импортируются через `tests.*`, не через точку входа.
- Сохраняйте дизайн, размеры форм, шесть разделов, исторические снимки/цены и последовательность статусов. Не добавляйте подсистемы без запроса. Избегайте лишних уровней и файлов.

# SQLite и сохранность

- Обычный запуск открывает `%LOCALAPPDATA%\AutoService\autoservice.db`; demo и снимки не открывают рабочую БД.
- Не используйте пользовательскую БД в тестах, диагностике или демонстрациях. Базы тестов создавайте только в TemporaryDirectory внутри `.tmp/` и закрывайте все соединения до удаления.
- Не удаляйте и не пересоздавайте существующую БД для исправления ошибки. Не меняйте схему без необходимости и миграции.
- Перед миграцией существующей БД обязательна проверенная online-копия SQLite с новым именем в соседней `backups/`. Не перезаписывайте копии; отказ копирования блокирует миграцию. Проверяйте откат и повторный запуск.
- Запись атомарна через Database.transaction()/SAVEPOINT. `write=False` предназначен для согласованных чтений без BEGIN IMMEDIATE. Не обходите проверку состава и суммы перед COMMIT.
- Завершённые заказы/позиции неизменяемы. Оставшиеся услуги сохраняют исторические цены, новые читаются из каталога внутри транзакции.
- UI обновляйте после успешного COMMIT, сохраняйте общие коллекции на месте. Ошибка сохранения не должна терять данные формы или показывать незафиксированную запись.

# Команды и проверки

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe main.py --demo
.\.venv\Scripts\python.exe -m unittest -v tests.test_storage_safety tests.test_order_editing
.\.venv\Scripts\python.exe -m unittest discover -v
```

- Запускайте целевые тесты для затронутых модулей. Перед релизом или общим рефакторингом выполняйте полную регрессию, если пользователь не задал иной порядок.
- Сохраняйте полезные старые проверки; обновляйте импорты при перемещении модулей. Не ослабляйте проверки ради зелёного результата.
- Перед коммитом проверяйте diff/status и отсутствие изменений документационных PNG от тестов.
- Пользовательские скриншоты и изображения README хранятся в `screenshots/`. Старые изображения сохранены для отчётов, не удаляйте без проверки ссылок.
- **Автоматические тесты пишут PNG только в `.tmp/test-screenshots/` через `tests.support.SCREENSHOTS`**, а не в отслеживаемый screenshots/. Остальные временные результаты размещайте в `.tmp/` или системном TemporaryDirectory. Не создавайте мусор в корне.
- README описывает актуальное приложение и команды, без истории лабораторных этапов. При изменении запуска, архитектуры или хранения обновляйте README/инструкцию Windows.
- `.venv/`, `.tmp/`, кэш, EXE, архивы сборки, локальные БД, backup и секреты не входят в Git. Не применяйте force push/reset --hard.
- Сборка: `powershell -ExecutionPolicy Bypass -File .\build.ps1` после установки requirements-build.txt. Не собирайте EXE без явного запроса; отличайте статическую проверку конфигурации от проверки готового EXE.
